# 指示文：iOS版エディター画面の再設計（Web版に学ぶ + シンプル化）

> 対象ファイル: `src/app/editor.tsx`（＋ `src/components/controls.tsx`, `src/data/music.ts`, `src/types/index.ts`, `src/theme/tokens.ts`）
> 参照: Web版 Chord Palette のUIスクリーンショット（ダイアトニック / 応用 / オンコードの3状態）

---

## 目的

Web版の優れたUX構造を取り込みつつ、iOS MVPとして「**コードを選ぶ → 進行に足す → 再生する**」のコアループを最短・迷わず回せるエディターにする。機能を増やすより、**主役（コード選択と進行）を際立たせる**ことを優先する。

---

## Web版から抽出した学び

### 採用したい優れた要素
1. **「コードライブラリ」と「進行」の明確な分離**：下部に大きく browsable なコード選択エリア、上部にコンパクトな進行ストリップ。役割分担が明快。
2. **カテゴリのタブ化**：`ダイアトニック / 応用 / オンコード` で高度なコードを整理（散らからない）。
3. **コードカードの情報階層**：度数(小) → **コード名(主役・大)** → 7th差分ピル → `T/SD/D` バッジ＋機能ドット。ひと目で機能が分かる。
4. **設定のコンパクト集約**：LEN/BPM/DRUM/BEAT/TONE を1枚のパネルに凝縮。
5. **ライブラリの折りたたみ**（chevron）で進行編集に集中できる。
6. **空状態のガイド**：「下のコードから選んで追加 ↓」で初見でも操作が分かる。

### 現iOS版の課題（シンプル化すべき点）
- **1画面に詰め込みすぎ**：基本設定＋ダイアトニック＋進行＋操作＋小節長＋再生＋演奏設定＋音量＋書き出しを全部縦積み。
- **コード選択が貧弱**：47pt幅の小カード（名前＋度数のみ）。機能バッジ・7th差分なし。
- **応用/オンコードが存在しない**（sus4/add9の2ピルだけ）。
- **演奏設定が `/groove` と重複**（音色/ドラム/パターン/音量）→ エディターの主目的をぼかしている。

---

## 守る原則（シンプルさ）

1. コアループ最優先。初見で「下から選んで上に足す」が分かること（空状態ヒント「下のコードから選んで追加 ↓」を踏襲）。
2. プログレッシブ・ディスクロージャー：既定は **ダイアトニック**。応用/オンコード/バリエーションはタブ・展開で段階的に。
3. 編集詳細（小節長・複製・移動・削除）は **選択中のときだけ文脈表示**（常時全部並べない）。
4. 演奏の細部（音色/ドラム/伴奏パターン/音量）は **エディターから外し、既存 `/groove` に集約**。エディターには小さなサマリー＋導線のみ。
5. 独自の色・サイズを作らず `theme/tokens.ts` に従う。

---

## 画面レイアウト（上→下）

1. **ヘッダー（コンパクト）**：アプリ名 / キー選択ドロップダウン / Undo / 保存 / 閉じる。
2. **トランスポート＆設定バー（1枚パネル）**：BPM（＋TAP）/ メトロノーム / ループ / 再生ボタン。音色・ドラムは小さなサマリーチップ（タップで `/groove`）。
3. **進行ストリップ**：`KEY: C` 見出し＋横スクロールのコードカード（`→` で連結）。空なら中央にヒント。選択カードはグロー（現行 `timeCardSelected` を踏襲）。
4. **選択時インライン操作**：選択中のみ表示 → 小節長セグメント / 複製 / 左右移動 / 削除（現行ロジックを流用）。
5. **コードライブラリ（主役・折りたたみ可）**：タブ `[ダイアトニック / 応用 / オンコード]` ＋ 大きめカードのグリッド（横スクロールではなく2行グリッド）。右上 chevron で開閉。

---

## コードカード仕様（ライブラリ）

- 上段：度数（IV, vii° 等）小さめ＋機能ドット。
- 中央：**コード名を主役に大きく**（F, Am/G 等）。
- 下段：7th等のサブ表記をピル（FM7 等）＋ `T/SD/D` バッジ。
- タップで進行末尾に追加（現行 `addChord` と16小節上限を維持）。
- Pro専用は錠アイコン＋沈んだ配色（`surfaceLocked` / `gold`）。

---

## タブ内容

- **ダイアトニック**：I〜vii°（既存 `diatonicSevenths`）＋下部に「度数を選んでバリエーション適用」（5th/sus2/sus4/9/11/13…）。※現状の sus4/add9 ピルをこの形へ発展。
- **応用**：セクション見出し付き（⚡SECONDARY DOMINANT / 🌙MODAL INTERCHANGE）。
- **オンコード**：対象コード表示＋ベース音グリッド（/C … /B）。

---

## データ/ロジック追加（@generator）

現状 `music.ts` はダイアトニックのみ。以下が必要：

- セカンダリードミナント（V7/ii〜V7/vi）。
- モーダルインターチェンジ（IVm, vm, ♭VII, ♭VI, ♭III …）。
- オンコード（スラッシュ：対象コード＋ベース音）。
- 型拡張（`ChordEvent` にベース音／バリエーション情報）。

---

## 機能色の統一（要判断）

- Web版：T=**青** / SD=黄 / D=赤。
- 現トークン：T=**緑**（`#22c55e`）/ SD=黄 / D=赤。
- **推奨**：Claude Design mock由来のトークンを正として **緑T/黄SD/赤D で統一**。Webの青Tに寄せる場合は `tokens.ts` の `tonic` を更新し全画面へ反映（generator/designer両方に影響）。

---

## スコープ外（やらないこと）

- 実際の音声再生エンジン実装（別スプリント）。
- ログイン/クラウド（MVP対象外）。
- 新規ルート乱立（応用/オンコードはエディター内タブで完結）。

---

## 受け渡し

- 構造・データ・ロジック → **@generator**
- 仕上げ（余白・階層・機能色・ダーク質感）→ **@designer**
- 完了後 **@evaluator** で4基準（デザインの質・オリジナリティ・クラフト・機能性）をチェック
