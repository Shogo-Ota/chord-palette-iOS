## 2. 変更内容の要約

1. **診断性向上（Phase 1）** — ネイティブ側に再生イベントログ（play / pause / stop / resume / 割り込み / ルート変更 / 音源切替 / エンジン再構成）と、スケジュール済みノート音域（`planNoteMin/Max`）・ピークポリフォニーの記録を追加。JS から `audioService.getPlaybackDiagnostics()` で取得可能。
2. **ポリフォニー上限（Phase 1）** — レンダーコールバックの1フレームあたり最大24声。超過時は古いテール側から間引き（新しいアタック優先）、超過量をカウンタに記録。病的な重なりによる CPU 飽和（「低音だけが鳴る」の有力仮説）を抑止。
3. **ベース改善（Phase 7）** — Root / Fifth / Octave / Passing / Approach を扱うプランナー。リズム別プロファイル、次コードのルート参照、跳躍・音域制限、強拍は安定音優先。
4. **フレーズ変化（Phase 8）** — 4小節単位で 2〜3小節目に軽いスタブ追加、4小節目（最終小節を除く）は末尾を間引いて次へつなぐ。
5. **トップノート強調（Phase 4）** — 同時発音の最高音を +3、内声を −1（スタイル別に調整可能）。
6. **軸モデル（Phase 2）** — 既存13リズムを Style × Feel × Role に解決するモデル。既存の音は不変。
7. **パターンライブラリ形式（Phase 12）** — 拍相対・度数相対・オクターブ相対の登録形式とバリデーション。生MIDIは保持しない。
8. **品質評価基盤（Phase 9/10）** — 固定進行 A〜D、定量メトリクス、レポート生成、MIDI整合性・決定性・ストレステスト。

## 3. 修正した不具合

- 「低音だけが鳴る」問題そのものは再現手段がないため**根治ではなく診断性向上＋防御**（イベントログ・音域記録・ポリフォニー上限）で対応。次回発生時に `getPlaybackDiagnostics()` の `planNoteMin/Max`（計画側は健全か）と `cappedVoiceFrames`（上限が作動したか）で JS 側/ネイティブ側の切り分けが可能。
- ベースの経過音が疎なパターンで長く残る問題（実装中に発見）: 次のルートが1拍以内に発音する場合のみ経過音・アプローチ音を適用するガードを追加。

## 6. 手動確認手順（Dev Client 再ビルド後）

1. `eas build --profile development --platform ios` → 実機へインストール。
2. 進行を作成し再生 → 従来どおり全パートが鳴ること（ポリフォニー上限のデグレなし）。
3. 13リズムを一通り切替 → それぞれ従来の性格が保たれ、ベースに動きが増えていること。
4. 再生中に着信 / イヤホン抜き差し / バックグラウンド往復 → 復帰後に再生・再開が正常。
5. Metro コンソールで `audioService.logPlaybackDiagnostics('manual')` を呼ぶ（または一時的なデバッグボタン）→ events に play/pause 等が時系列で並び、`peakPolyphony` が常識的な値（〜15）で `cappedVoiceFrames = 0` であること。
6. 30分以上の連続再生 → 異常発生時は手順5のスナップショットを取得して報告。
7. 動画書き出し → 音と映像のコード切替が一致（既存自動テストでも担保）。

## 8. 未解決の問題
