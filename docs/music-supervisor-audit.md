## 0. 総評（結論サマリ）

- **土台は良い**。度数対応テンション（`music.ts` の `DEGREE_VARIATION_SUFFIX`）は avoid-note を理解した設計で、音楽理論的に非常に堅実。伴奏の「食い(look)＋微小タイミング揺らぎ＋ベロシティ波」も方向性は正しい。
- **最大の弱点は「ボイスリーディングが実質ゼロ」**。全コードが固定レジスター（C3=MIDI 48）のルート・ポジションで鳴るため、進行がブロック的に跳ね、"曲のたたき台"としての説得力が削がれている。**これは要件 §5.5「基本的なボイスリーディングを自動適用する」を満たしていない仕様未達**でもある。→ 最優先(P0)。
- **合成ドラム／音色はスマホ内蔵スピーカー前提のチューニングが甘い**。キックが純サイン（クリック無し）で内蔵スピーカーでは芯が消える。低音2オクターブ重ね（C1+C2）は密室ヘッドフォンでは濁り、スピーカーでは無駄なヘッドルーム消費。→ P1、低工数・高ROI。
- **プリセットに理論上のラベル不整合**（「王道進行」が I-V-vi-IV になっている）。データ修正のみでリスクほぼゼロ。→ P1。

## 1. 優先度付き改善提案

### P0 — リリース必須

#### P0-1. コードにボイスリーディング（転回形選択）が無く、進行がブロック的に跳ねる
- **症状**: I→V→vi→IV のような基本進行でも、各コードが毎回 C3 のルート・ポジションで鳴るため、和音の"塊"が上下にジャンプして聞こえる。トップノートの旋律的な連結が生まれず、単発の試聴では気づきにくいが、ループ再生・動画書き出しで「打ち込み感／貼り付け感」が強く出る。
- **音楽的理由**: 鍵盤伴奏の自然さは「共通音の保持」と「最短距離での声部移動（トップノートが滑らかに動く）」で決まる。現状は `chordMidiNotes()` が前のコードを一切参照せず、各和音を独立に `CHORD_ROOT_MIDI = 48`（`src/lib/voicing.ts` L14）からのルート・ポジションで生成しているため、声部連結の概念が存在しない。要件 §5.5 も「コード遷移が不自然になりにくいよう、基本的なボイスリーディングを自動適用する」と明記しており、**現状は DoD 未達**。
- **具体的な変更**:
  - 対象: `src/lib/voicing.ts`。`progressionToChordSpecs()`（L91）に「直前コードのボイシングを引き継いで次コードの転回形を選ぶ」パスを追加する（純ロジックなので単体テスト可）。
  - アルゴリズム案（軽量で十分効く）: 各コードの body 音（`chord.suffix` の INTERVALS 展開）について、ルート位置から ±1 オクターブの転回形候補を作り、**直前コードのトップノート（または各声部の重心）との合計移動距離が最小になる転回形を選ぶ**。目標レジスターは C3〜C4 付近にクランプ（レジスタードリフト防止）。
  - ベース（`SUB_BASS_ROOT_MIDI`/`BASS_ROOT_MIDI`, L16/L22）はコード・ルート（またはスラッシュ・ベース）に固定したまま、上物の body だけ転回させる（「ベースはルート、上物は滑らかに」というポップ／ピアノの定石）。
  - 新規ファイル化推奨: `src/lib/voiceLeading.ts` に転回選択関数を切り出し、`voicing.ts` からは呼ぶだけにする（拡張性ルール準拠・既存改変を最小化）。
- **担当**: @generator（純ロジック／型定義・単体テスト付き）
- **実機検証方法**: 王道系 4 コード（C→G→Am→F）を Block と 8beat で再生。トップノートが半音〜数半音以内で滑らかに動くか、和音の"ジャンプ感"が消えたかを聴く。変更前後の書き出し MP4 を比較すると差が明確。

#### P0-2. 低音2オクターブ重ね（C1）が実機スピーカーで濁り／無駄になる
- **症状**: 全コードで C1(MIDI 24)＋C2(MIDI 36) を常時重ねている（`voicing.ts` L85 `bass`）。ヘッドフォン／良いスピーカーでは "ブーミー"、iPhone 内蔵スピーカーでは C1(≈32.7Hz)〜C2(≈65Hz) がほぼ再生されず、ヘッドルームだけ食って中域が痩せて聞こえる。8beat/16beat では毎拍この2音が鳴るため、混変調で低域がモコつく。
- **音楽的理由**: ポップ／ピアノのローエンドは通常「1オクターブ（＋必要なら5度）」で十分で、サブオクターブ・ダブリングは基音同士の唸り（beating）と位相打ち消しを招きやすい。特にモバイルの主聴取環境（内蔵スピーカー）は ~150Hz 以下が出ないため、C1 は"音"ではなく"濁りの種"になりがち。
- **具体的な変更**:
  - 対象: `src/lib/voicing.ts` L85。サブベース C1 を**常時重ねから外す**か、少なくとも **gain を下げて重ねる**（現状は body と同ゲイン）。案: ベースは C2 を主とし、C1 は任意（例: 内蔵スピーカー時は無効、ヘッドフォン時のみ薄く）。
  - もしくは `AudioEngineController.swift` の `emitGroup`（L643）で `isBass` 選択時に **サブベース側だけ gain を 0.5〜0.6 に減衰**させる（`baseVel` 計算箇所 L666 付近）。
  - 併せて Mixer 側（`buildEngine` L300-302 の `setChordVolume(0.85)`）とローエンドの兼ね合いを実機で再チューニング。
- **担当**: @generator（`voicing.ts` のベース構成、または Swift の bass gain）
- **実機検証方法**: iPhone 内蔵スピーカーとイヤホンの両方で、単一コード長押し試聴と 8beat ループを比較。「中域（コードの色）が痩せていないか」「低域がモコつかないか」を A/B。

### P1 — 強く推奨

#### P1-1. 合成キックにアタック（クリック）が無く、内蔵スピーカーで芯が消える
- **症状**: `DrumProvider.swift` の `.kick`（L131-136）は 120→45Hz へ落ちる純サイン＋指数エンベロープのみ。良い再生環境では"ボスッ"と鳴るが、iPhone スピーカーでは低域が出ないため**存在感がほぼ消え、リズムの芯が失われる**。
- **音楽的理由**: モバイルでキックを"聞かせる"には、低域の基音だけでなく **アタック成分（ビーターのクリック＝100〜4kHz の短い過渡音）** が不可欠。内蔵スピーカーは基音を再生できないので、聴感上のキックは中高域のクリックが担う。
- **具体的な変更**: `voiceSample(.kick …)`（L131）に、冒頭 3〜8ms の短いクリック（高めのサイン or 帯域ノイズを急速減衰）を加算する。既存の `noise(frame)`（L175）を短エンベロープで流用可能。基音ピッチ落とし（L135）はそのまま維持。
- **担当**: @generator（Swift 合成音）
- **実機検証方法**: pop8/rock8 を内蔵スピーカーで再生し、キックが「聞こえる／位置が分かる」か。ヘッドフォンで低域が過剰になっていないかも確認。

#### P1-2. 合成スネアが細く／硬い（帯域整形なし・中域の"鳴り"不足）
- **症状**: `.snare`（L137-143）は 180Hz サイン＋フルバンド白色ノイズ。低めのトーンとザラついた白色ノイズで、"パン"というスネアの胴鳴りが薄く、グルーヴによっては安っぽく／耳に痛く聞こえる。
- **音楽的理由**: スネアの体感的な芯は 150〜250Hz の胴鳴り＋帯域制限したノイズ（~2〜8kHz）で作られる。フルバンド白色ノイズは高域が過剰でチープに、トーンが 180Hz 固定だと胴鳴りの密度が不足する。
- **具体的な変更**: `.snare` のトーンに 200Hz 前後の第2成分を足す／ノイズを簡易ハイパス（前サンプルとの差分で近似）してブライトすぎを抑える。エンベロープ（L140）は概ね良好。
- **担当**: @generator（Swift 合成音）
- **実機検証方法**: soul16/pop16 のバックビートで、スネアが「詰まって聞こえる／耳に痛くない」か。ゴーストノート（soul16 の 1.75/3.75, L96）が潰れず聞こえるか。

#### P1-3. プリセット「王道進行」のラベルと度数が音楽通例と不一致
- **症状**: `src/data/presets.ts` の `jpop-royal`「J-POP王道進行」が **I-V-vi-IV**（C·G·Am·F, L20-26）で定義。一方 `city-pop`「City Pop進行」が **IVmaj7-V7-iiim7-vim7**（=4536, L96-102）で定義されている。
- **音楽的理由**: 日本語の「王道進行」は通例 **IV-V-iii-vi（4536, FM7-G7-Em7-Am7）** を指す。現状の I-V-vi-IV はいわゆる "Axis/カノン系" や `pop-punk`（L66 で同一進行）に近い。つまり**「王道」ラベルが理論通例とズレ、かつ `pop-punk` と進行が完全重複**している。実際の 4536 は `city-pop` 側にある、というねじれ。
- **具体的な変更**: `src/data/presets.ts` のデータのみ修正。案:
  - `jpop-royal` を本来の 4536（IVmaj7-V7-iiim7-vim7 相当、または三和音版 F-G-Em-Am）に修正、`chordsDisplay`/`degreeLabel`/`chords` を更新。
  - もしくはラベルを実態に合わせ「Axis進行 / ポップ循環」等へリネーム。無料枠は §5.11 で「J-POP王道進行」が指定なので、**進行側を 4536 に直す**のが仕様適合。
  - `pop-punk` との重複（同じ I-V-vi-IV）も解消される。
  - 併せて `city-pop` と役割が被らないよう再整理（City Pop はテンション/オンコードで差別化）。
- **担当**: @generator（`presets.ts` データ）※法務リネーム（release-plan §5-3）と同時対応が効率的
- **実機検証方法**: 各プリセット選択→再生し、進行が意図どおり（4536 が"王道"らしい浮遊感で鳴る）か、`pop-punk` と区別が付くかを聴く。

#### P1-4. 伴奏の「sparkle（トップ+1オクターブ複製）」が全打点で入り、機械的に響く
- **症状**: `AudioEngineController.swift` の `emitGroup`（L659-666）で、`sparkle` 時にトップノート+12 を 0.5 ゲインで常時追加。Block は各コード頭（L799）、8beat は全ストローク（L718 `sparkle: true`）で発火する。ピアノで全打点にオクターブ上を重ねるのは非イディオマティックで、"ベル／シンセ的"な人工感が出る。
- **音楽的理由**: 生ピアノは高音オクターブを機械的に毎回重ねない。ブライトネス付与は「頭拍だけ」「弱く」「たまに」が自然。全打点ダブリングは倍音過多で音像が硬くなる。
- **具体的な変更**: `emitGrid`/`emitGroup` の `sparkle` を、8beat では**頭拍（beat 0/2）だけ**に限定、または gain を 0.5→0.3 程度へ下げる。Block はコード頭のみなので現状維持でも可だがゲイン再考の余地あり。
- **担当**: @generator（Swift 伴奏ロジック）
- **実機検証方法**: 8beat で高音の"チリチリ"したオクターブ重ねが目立たないか、ピアノらしい自然な明るさかを A/B。

### P2 — 余裕があれば

#### P2-1. ドラムのハット／ゴーストにベロシティの抑揚（ヒール&トゥ）が無い
- **症状**: `hats()`（L52-61）は「頭拍アクセント＋それ以外は一定 vel」。16beat 系（pop16/rock16/soul16）で 16 分ハットが一定ベロシティに並び、機械的（打ち込みハット感）。
- **音楽的理由**: 実際のハットは "ダウン強・アップ弱" の抑揚（heel-toe）で躍動する。裏拍を軽くするだけで一気に人間味が出る。
- **具体的な変更**: `hats()` に「拍裏（8分裏／16分の e,a）を段階的に弱く」する係数を追加。決定論性（seed 固定）は維持。
- **担当**: @generator。**検証**: pop16 のハットが"波打つ"感じになるか。

#### P2-2. 拡張和音（9/11/13）の声部間隔が下部で密になりやすい
- **症状**: `INTERVALS`（`voicing.ts` L44-57）は絶対スタック。`'13' = [0,4,7,10,14,21]` などはルート付近（0,4,7）が密でテンションが上に離れる。低いレジスター（C3）だと下部3度堆積が濁りやすい。
- **音楽的理由**: ジャズ／ポップの上級ボイシングは 5度や重複音を省いて "開いた" 配置にする（例: 13th は 5度省略・3rd/7th＋テンション）。現状は 5度(7)を残しつつ全部積むので密度が高い。
- **具体的な変更**: `INTERVALS` の拡張形で 5度(7) の省略や 9th を下オクターブに落とすなど、開離配置版を用意（P0-1 のボイスリーディングと統合すると効果大）。avoid-note 方針（`music.ts`）は既に良好なので INTERVALS 側の間隔設計のみ。
- **担当**: @generator。**検証**: Pro テンション（Cmaj13 等）を低音側で鳴らして濁りが減るか。

#### P2-3. プリセットのバリエーション拡充（カノン進行など）
- **症状**: 現状 6 種。丸サ／Just The Two of Us は同系統（IVM7-III7-vim7 …）で被り気味。定番の**カノン進行**（I-V-vi-iii-IV-I-IV-V）が無い。
- **音楽的理由**: 進行の"引き出し"の幅がアプリの魅力に直結。カノン／Just the way 系／ペダルポイント系など性格の異なる進行があると試作の楽しさが増す。
- **具体的な変更**: `presets.ts` にカノン進行（8 コード）等を Pro で追加（度数ベース、§5.8 準拠）。
- **担当**: @generator（データ）。**検証**: 転調（キー変更）しても度数維持で正しく鳴るか。

## 3. 領域別・所見（必須項目）

### 3.1 ボイシング（低音2オクターブ重ねの是非 / 転回形・トップノート連結 / テンション配置）
- **低音2オクターブ重ね（C1+C2）**: 発想（中域トライアドだけだと痩せる）は正しいが、**常時 C1 まで重ねるのは過剰**。ヘッドフォンで濁り、内蔵スピーカーで無駄。→ C2 主体＋C1 は減衰/条件付き（P0-2）。5度をベースに足す選択肢も検討価値あり。
- **転回形・トップノート連結**: **未実装が最大の課題**。全コードがルート・ポジション固定レジスターで、声部連結がゼロ。ここを入れると"打ち込み感"が最も大きく改善する（P0-1）。要件 §5.5 の明示要件でもある。
- **テンション配置**: `music.ts` の avoid-note 対応は**秀逸**（Ionian で♮11回避＝maj9/maj13、Mixolydian で 9/13、Aeolian で 6/13 除外 等、モードごとに正しく制御）。ここは高評価。改善余地は INTERVALS 側の"開離配置"（5度省略等）のみ（P2-2）。

### 3.2 伴奏4パターン（block / eightBeat / sixteenthBeat / arpeggio）
- **block**: 拍頭固定・シンコペ無し・ベロシティほぼ均一（velAmount 0.02）で方針どおり。ソフトロール（strumSec 0.012）＋sparkle でピアノ感。sparkle ゲインは要調整（P1-4）。
- **eightBeat**: ベース4分＋body 8分、裏拍に食い(look)とタイミング揺らぎ(0.018 beat≈9ms@120)、ベロシティ波。設計は正統で良い。sparkle 全打点だけが過剰（P1-4）。
- **sixteenthBeat**: ゴースト(e)＋"a"の食い(look 0.07)＋揺らぎ。16分の抑揚設計は良好。ringCap の un-pedal でクリア。**懸念**: rock16×16beat では打点密度が高く、ローエンド（P0-2）と相まって音割れ/濁りが出やすい（handoff §7 既知メモと一致）。P0-2 対応後に実機で再確認を。
- **arpeggio**: order `[0,1,2,3,4,2]` の 16分ブロークン＋ベース・ドローン。現状維持方針で問題なし。body 音数が少ない三和音でも wrap で破綻しない実装。
- 総評: **4パターンの"キャラの描き分け"は成立**している。ボイスリーディング（P0-1）が入ると全パターンが同時に上質化する。

### 3.3 ドラム7グルーヴ（合成音色）
- **パターン設計は良質**: jazzSwing のライド3連（`1.0+2.0/3.0`）＝正しいスウィング、soul16 のゴースト、bossaNova のクロススティック・クラーベ風、rock は強めのバックビート等、7種の性格分けは音楽的に妥当。
- **合成音色が弱点**: キックにアタック無し（P1-1）、スネアがフルバンドノイズで細い/硬い（P1-2）、ハット/ゴーストにベロシティ抑揚無し（P2-1）。**サンプル化は V2 方針（release-plan §5-2）なので、合成の作り込みが唯一のレバー**。P1-1/P1-2 だけでも内蔵スピーカーでの説得力が大きく上がる。
- ride/rim/hat の合成は概ね良好。

### 3.4 プリセット進行の音楽的完成度
- **個々の進行は良い**: 丸サ（IVM7-III7-vim7-I7）、Just The Two of Us（…-vm7-I7 の ii-V 挿入）、小室（vi-IV-V-I）、City Pop（4536）はいずれも理論的に正確で"らしい"。III7＝V7/vi のセカンダリードミナント活用も◎。
- **問題は「王道進行」のラベル/度数不整合**（P1-3）と `pop-punk` との進行重複。**修正必須級**（データのみ）。
- **拡充余地**: カノン進行など性格の異なる定番の追加（P2-3）。丸サ／Just the Two は同系統なので、Pro の"幅"を出すなら別系統を足すと魅力が増す。
- 法務: 曲名由来プリセット名は §5.8／release-plan §5-3 のとおり一般名称化を M5 で。音楽監修としても「特定録音物の再現ではない」表現に賛同。
