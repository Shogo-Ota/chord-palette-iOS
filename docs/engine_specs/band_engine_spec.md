## 1. Band Engine がユーザーへ提供する体験

- コード進行を並べて Band を選ぶだけで、**前へ進む王道バンドの伴奏として成立する演奏**が返ってくる。操作は従来どおり「コード・テンポ・スタイル」のみ（vision §10 UX原則）。
- 目指す聴感（教材要素10項目の言い換え）:
  - 8ビートの推進力が主役で、**止まらず前へ進む**
  - ベースが刻みでドライブし、サビ相当の位置で開放感が出る
  - フィルイン的な変化が4小節の変わり目に入り、単調にならない
- 非目標: 実ギター音色の再現（現行エンジンはピアノ系コンプ＋ベース＋キット）。特定曲の再現。セクション自動判定は v1 では行わない。
- **制約（正直さの原則）**: 教材要素の「ギターストローク／アルペジオ」は現行の楽器編成では出せない。v1 では**ピアノ系コンプの刻みとアクセントで役割を翻訳**し、ギターの導入は `InstrumentRole = 'guitar'`（軸モデル定義済み）の将来課題として明示する。

## 2. 仮説としての共通伴奏特徴

教師8曲（車輪の唄、怪獣の花唄、キセキ、Sharon 等）の傾向として、以下を作業仮説とする。**いずれも音源解析による確認前**。

| # | 仮説 | 根拠の種類 |
|---|------|-----------|
| H1 | テンポ帯はおおむね 85–140 BPM。ミドル〜アップの歌モノロック | 一般的知識（仮説） |
| H2 | 8ビートが基本。サビや疾走曲で16ビート化・シンバル増 | 教材要素リスト＋一般的知識（仮説） |
| H3 | コード楽器は表拍＋裏拍の混在ストロークで、刻みは持続よりアタック重視 | 一般的知識（仮説） |
| H4 | ベースはルート8分刻みが基本で、コード変わり目に経過音・アプローチが入る | 教材要素リスト（仮説） |
| H5 | ドラムはキック1・3＋スネア2・4の生8ビートが軸。フィルは4・8小節目 | 教材要素リスト（仮説） |
| H6 | Aメロは刻み薄め、サビで全パートが開く（バンド全体のダイナミクス） | 教材要素リスト（仮説） |
| H7 | 4小節目にフィルインまたは食い（アンティシペーション）で次のフレーズへ渡す | 教材要素リスト（仮説） |
| H8 | パート間の役割分担が明確: ベース＝推進、コード＝面、ドラム＝骨格 | 教材要素リスト（仮説） |
| H9 | ベロシティはバラードより高域に寄り、アクセント差で疾走感を出す | 一般的知識（仮説） |
| H10 | 裏拍のプッシュ（8分裏の食い）がサビ前後で増える | 一般的知識（仮説） |

検証時は、各仮説に対して「支持する曲 / 反例となる曲」を教師データの
「教材として見るべき伴奏要素」列に記入していく。

## 3. 必要なピアノ（コンプ）パターン（仮説に基づく候補）

既存の `beat8` リズム（8 Beat）と variants が Band の出発点。Ballad と違い、**既存資産が既にかなり近い**。

| ID 案 | 内容 | 対応仮説 | 既存資産 |
|---|---|---|---|
| `band.straight` | 表拍＋裏拍混在の標準8ビート刻み | H2, H3 | `beat8.pop`（既存） |
| `band.simple` | 1・3拍のみの刻み（Aメロ向け・薄い） | H6 | `beat8.simple`（既存） |
| `band.drive` | 食いを1拍前まで広げた前のめり | H7, H10 | `beat8.drive`（既存） |
| `band.sixteen` | 16分混在の刻み（サビ・疾走曲向け） | H2, H6 | `beat16` 系の流用可否を実装時判定 |
| フレーズ終端形 | 4小節目のフィル的変化（stab 追加 or 食い） | H7 | `twoFourBar`/`phraseFill` の調整 |

- v1 の主作業は**新パターンの追加ではなく、既存 `beat8` の質の引き上げ**（velocity プロファイル・フレーズ変化・バリアント間の性格差の明確化）とする。

## 4. 必要なベースパターン（仮説に基づく候補）

既存 `BassProfile` のエントリ調整・追加として定義する。

| ID 案 | figures | 特徴 |
|---|---|---|
| `BAND_DRIVE` | rootOnly 中心（8分連打） | 同音刻みの推進力が価値（H4）。ピッチではなく**打点密度**で走る |
| `BAND_MOVE` | rootFifth + rootOctave | サビ相当・変化枠。オクターブポンプで開放感（H6） |
| `BAND_CONNECT` | 上記 + passing/approach 高め | コード変わり目のウォークアップ／ダウン（H4, H7） |

- 現行 `beat8` は `POP_LINE`（rootFifth + approach 0.5）。**8分の同音連打**（打点追加）は現行プランナーの守備範囲外（ピッチのみ変更）なので、必要ならスケルトン側（`eightBeat` の bass hits）の密度バリアントとして扱う。
- 強拍ルート・音域制約・1拍ガードは既存プランナーの原則をそのまま適用。

## 5. 必要なドラムパターン（仮説に基づく候補）

| ID 案 | 内容 | 用途 |
|---|---|---|
| （流用）`pop8` / `rock8` | 既存の8ビート生ドラム | 基本形（H5）。まず流用可否を検証 |
| `bandFill4` | 4小節目にタムフィルを足した変化形 | H7。**ネイティブ追加＝要再ビルド**のため v1 では見送り候補 |

- Ballad 同様、v1 は**既存パターンの流用を先に検証**し、不足が実機で確認された場合のみネイティブ追加を計画する。

## 6. ギターの役割（将来）

- 位置づけ: **v1 では実装しない**。`InstrumentRole = 'guitar'` の最初の適用先として方針のみ固定する。
- 方針（仮説）:
  - ストローク＝面（コードを幅広く、アタックで刻む）、アルペジオ＝線（Aメロの隙間埋め）
  - ピアノコンプと同時に鳴らす場合は音域・リズムをずらして衝突を避ける（H8）
  - 実装にはネイティブ音源追加（サンプル＋レンダリング）が必要＝要再ビルド・要素材ライセンス確認

## 7. Humanize 方針

既存の決定論的 Humanize 層をそのまま使い、**Band 用のプロファイル値**だけを定義する。

- タイミング: バラードより**タイト**（humanizeScale 0.8〜0.9 目安。現行 driving の 0.82 が参考値）
- 前ノリ: レイドバックさせない。微小な前倒しは食い（anticipation）で表現し、microtiming は中立〜わずかに負
- ロール感: 刻み主体のためブロックのロールは最小限
- 再現性: 同じ進行・同じ seed で同じ演奏（既存 determinism 保証を維持）
- 数値は実装フェーズで `balladCalibration` 同様のキャリブレーションテストとして固定する

## 8. ボイシング方針

- 共通音保持・最小移動は既存 `voiceLeading.ts` の枠内
- バラードよりクローズ気味・中域寄せを許容（刻みの「面」を作る）
- ベースがルート刻みを持つため、コンプ左手の低域ルート重複は避ける
- テンションはユーザー指定分のみ（既存方針の踏襲）

## 9. ダイナミクス方針

- ベロシティ中心はバラードより高め、**アクセント差（表拍 vs 裏拍）で疾走感**を作る（H9）
- 4小節フレーズ: 2–3小節目の stab 付加を Ballad より積極的に、4小節目は「間」ではなく**フィル的な食い**で次へ渡す（H7 — Ballad と正反対の性格付け）
- サビ相当の段階変化（周回数ベース）は v2 候補（Ballad 仕様 §9 と共通）

## 10. 実装に必要なデータ構造

Ballad 同様、新規の型はほぼ不要で既存構造のエントリ追加・調整で成立する見込み。

| 構造 | 場所 | Band での使い方 |
|---|---|---|
| `RhythmAxes` | `src/lib/performance/model/` | `style: 'band'`（beat8/natural/driving/shuffle/swing/reggae は分類済み） |
| `StylePreset` | `src/lib/performance/styles/eightBeat.ts` | velocity / accent プロファイルの引き上げ |
| `BassProfile` | `src/lib/performance/bass/profiles.ts` | §4 のプロファイル調整 |
| `AccompanimentVariant` | `variants/catalog.ts` | `beat8` 系バリアントの性格差強化 |
| `VariationProfile` | `feel/profiles.ts` ほか | フレーズ終端のフィル的性格（§9） |
| `LibraryPattern` | `src/lib/performance/library/` | §13 の教材 MIDI の相対化登録先 |
| 教師データ | `docs/style_datasets/band_teacher.md` | 仮説の出典と検証結果の記録先 |

## 11. 最小構成の Band Engine v1

**スコープ（これだけ作る）**:

1. `beat8` のベロシティ／アクセントプロファイルを Band らしく調整（表裏のアクセント差を明確に）
2. フレーズ終端の性格付け: `beat8` 系の 4小節目を「間」ではなく食い・stab 寄りに（`EIGHT_VARIATION` / `phraseFill` の調整）
3. ベース: `beat8` のプロファイルを `BAND_DRIVE`/`BAND_MOVE` の考え方で見直し（approach 頻度・オクターブポンプの使い分け）
4. キャリブレーションテスト（`bandCalibration.test.ts`）で数値凍結
5. スタイルカード（実装済み）の Band 推奨リズムが `beat8` のままで良いかの最終確認

**やらないこと**: ギター音色、ネイティブドラム追加（フィル）、セクション自動判定、周回数ダイナミクス、他スタイル。

**接続方法**: 既存 `beat8` リズムと variants の調整で実現し、保存形式・課金・他リズムには触れない。UI は実装済みのスタイルカード（Band → beat8）をそのまま使う。

## 12. 検証方法

1. **定量**: `ACCOMPANIMENT_REPORT` で before/after を生成し、beat8 エントリの音数・ベロシティ標準偏差・タイミング偏差を比較
2. **不変条件**: 既存 `midiIntegrity` / `determinism` / `stress` を全パス
3. **聴感チェックリスト（実機）**: 固定進行 A〜D を Band（beat8）で再生し、
   - 前へ進む推進力を感じるか（H2/H9）
   - 4小節目で次のフレーズへ「渡る」感じがあるか（H7）
   - Ballad との性格差が明確か（§9 の正反対の性格付け）
   を主観3段階で記録する。判定者はオーナー。
4. **仮説の検証**: §13 の教材 MIDI が用意でき次第、`LibraryPattern` 形式へ相対化して H1〜H10 と突き合わせる
5. **回帰**: beat8 以外のリズムのレポート数値が変化していないこと

## 13. 合法的に用意すべき MIDI 教材の条件

Ballad 仕様 §13 と同一（`docs/midi_dataset_policy.md` / `docs/midi_sources.md` に従う）。

1. オーナー自身の演奏・打ち込みによるオリジナルの伴奏パターン
2. 明示的ライセンスで再利用可能な MIDI（CC0 / CC-BY 等）
3. パブリックドメイン楽曲の権利上問題のない打ち込み
4. 購入・許諾済みでアプリ組み込みが許される商用 MIDI ライブラリ

登録は `docs/style_datasets/midi_registry.json` に権利情報込みで行い、
`verificationStatus: 'verified'` かつ `derivativeUseAllowed: true` のもののみ取り込む。
