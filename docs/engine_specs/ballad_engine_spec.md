## 1. Ballad Engine がユーザーへ提供する体験

- コード進行を並べて Ballad を選ぶだけで、**歌モノのバラードの伴奏として成立する演奏**が返ってくる。ユーザーが操作するのは従来どおり「コード・テンポ・リズム（スタイル）」だけで、新しい専門操作を増やさない（vision §10 UX原則）。
- 目指す聴感（教師データの「教材として見る伴奏要素」10項目の言い換え）:
  - ピアノが主役で、**音数より余白と持続**で聴かせる
  - 同じコードでも4小節の中で表情が変わり、フレーズ終端で呼吸する
  - 上に歌が乗ることを前提とした密度（**鼻歌を邪魔しない**）
- 非目標: 特定の楽曲の再現。ピアニストの即興の完全な模倣。セクション構造（Aメロ/サビ）の自動判定は v1 では行わない（§11）。

## 2. 仮説としての共通伴奏特徴

教師18曲（First Love、奏、ドライフラワー、Someone Like You、All of Me 等）の傾向として、以下を作業仮説とする。**いずれも音源解析による確認前**。

| # | 仮説 | 根拠の種類 |
|---|------|-----------|
| H1 | テンポ帯はおおむね 60–90 BPM、バラードとして遅め | 一般的知識（仮説） |
| H2 | ピアノはブロックコード保持とアルペジオの2系統が主体で、1拍ごとの刻みは少ない | 教材要素リスト＋一般的知識（仮説） |
| H3 | ペダルによる響きの重なり（前のコードの余韻が次の頭に薄く残る）がある | 一般的知識（仮説） |
| H4 | ベースはルート中心の全音符〜2分音符で、コード変わり目に経過音が入る程度 | 一般的知識（仮説） |
| H5 | ドラムは無し・薄いブラシ・静かな8ビートの3段階があり、常時強いキックは無い | 一般的知識（仮説） |
| H6 | Aメロは疎、サビで密度とベロシティが上がる（セクション間ダイナミクス） | 教材要素リスト（仮説） |
| H7 | フレーズ終端（4小節目・8小節目）で音数を減らすか長い音で受ける | 教材要素リスト（仮説） |
| H8 | トップノートがメロディックに緩やかに動き、跳躍は少ない | 一般的知識（仮説） |

## 3. 必要なピアノパターン（仮説に基づく候補）

既存の `AccompanimentPattern`（rhythms 層）と `AccompanimentVariant` の枠組みに載せる想定。

| ID 案 | 内容 | 対応仮説 |
|---|---|---|
| `ballad.hold` | ブロックコードを小節頭で置き、持続。ペダル的な重なり（次コード頭へ僅かに残す） | H2, H3 |
| `ballad.arp.slow` | 8分音符主体の低→高アルペジオ。1〜2拍目で上り、後半は保持 | H2 |
| `ballad.arp.flow` | 8分〜16分の流れるアルペジオ（サビ向け・密度高） | H2, H6 |
| `ballad.pulse` | 2拍ごとの柔らかい再打鍵（ブロックとアルペジオの中間） | H2 |
| フレーズ終端形 | 上記各パターンの4小節目変化形（音数減 or 全音符受け） | H7 |

- 既存の `ballad` リズム（実装済み）は `ballad.hold` 相当の出発点として流用可能か、実装フェーズで判定する。
- 左手（ルート＋5度）と右手（3〜4声）の分担は既存 voicing 層の音域制約で表現する。

## 4. 必要なベースパターン（仮説に基づく候補）

既存の `BassProfile`（`src/lib/performance/bass/profiles.ts`）の追加エントリとして定義する。

| ID 案 | figures | 特徴 |
|---|---|---|
| `BALLAD_ROOT` | rootOnly 中心 | 全音符〜2分音符。動かないことが価値（H4） |
| `BALLAD_WARM` | root + fifth + octave 低頻度 | コード後半で5度に降りる程度。approachChance 低 |
| `BALLAD_CONNECT` | 上記 + passing/approach | コード変わり目の直前1拍以内のみ経過音（既存プランナーのガードと整合） |

- 強拍は常にルート（既存プランナーの原則をそのまま適用）。
- 音域は既存の bass レジスタ制約（E1〜G2 相当）を踏襲。

## 5. 必要なドラムパターン（仮説に基づく候補）

ネイティブ `DrumKit.swift` のパターン追加が必要になる想定（要再ビルド領域）。

| ID 案 | 内容 | 用途 |
|---|---|---|
| `balladNone` | 無音（ドラムなし） | 最小密度。既存のドラム音量0で代替可能か実装時に判断 |
| `balladBrush` | ブラシ風の薄い2・4拍＋控えめなハット | H5 の中間段階 |
| `balladSoft8` | 静かな8ビート（弱いキック1・3、サイドスティック2・4） | サビ・後半用 |

- 既存 `drumPatternFor` のオーバーライド機構（`src/lib/performance/rhythms/drumPattern.ts`）に載せる。
- キックの音量・頻度は「歌を邪魔しない」を最優先（H5）。

## 6. ストリングスの役割

- 位置づけ: **v1 では実装しない**（§11）。ただし将来の `InstrumentRole = 'strings'`（軸モデルに定義済み）の最初の適用先となるため、方針だけ固定する。
- 方針（仮説）:
  - 持続音（全音符）でコードの上3声を薄く重ねる。刻まない（H9）
  - 入るタイミングはフレーズ単位（例: 2周目以降・後半4小節から）で、突然入れない
  - 音域はピアノの右手より上〜同域。ベースと被る低域には置かない
  - ダイナミクスはピアノより一段小さく、クレッシェンドで支える
- 実装前提: 現行ネイティブエンジンは chord/drums の2系統ミックスであり、第3トラックの追加はネイティブ変更（要再ビルド）を伴う。代替案として「ピアノの chordEvents に長い持続声部を混ぜる」方式も検討する（実装フェーズで判断）。

## 7. Humanize 方針

既存の決定論的 Humanize 層（microtiming / velocity / articulation、seed 固定）をそのまま使い、**Ballad 用のプロファイル値**だけを定義する。

- タイミング: ピアノは中程度（現行 natural 同等か僅かに大きめ）、ベースは小、ドラムは極小。BPM 依存の上限スケーリングは既存実装を踏襲。
- ロール感: ブロックコードの同時発音に 0〜15ms 程度の下から上への微小ずらし（コードグループを壊さない範囲、implementation §Phase 3）。既存 strum 機構の流用可否を実装時に確認。
- 再現性: 同じ進行・同じ seed で同じ演奏（既存 `determinism.test.ts` の保証を維持）。
- 数値はすべて実装フェーズで `naturalCompCalibration` 同様のキャリブレーションテストとして固定する。

## 8. ボイシング方針

既存 `voiceLeading.ts` の共通音保持・最小移動の枠内で、Ballad 固有の重みを付ける。

- 共通音保持を最優先し、トップノートの跳躍を強く抑制（H8）
- 右手は3〜4声。密集配置よりオープン気味を許容（低域の団子を避ける）
- ベーストラックがルートを持つため、ピアノ左手のルート重複を減らす方向（implementation §Phase 6 原則）
- テンションはユーザーがコードに付けたもののみ発音（エンジンが勝手に足さない — 既存方針の踏襲）

## 9. ダイナミクス方針

- ベロシティは既存 velocity 層（拍位置・トップノート強調 topEmphasis 実装済み）を使用し、Ballad プロファイルでは**幅を広めに**取る（H10）
- 4小節フレーズ内の起伏: 既存 `twoFourBar` のフレーズ位置変化を Ballad 向けに調整（2–3小節目の付加は控えめに、4小節目の「間」を深めに）（H7）
- セクション（Aメロ/サビ）の自動判定は行わない。代替として、**進行の周回数**で段階を上げる案（1周目: 疎 → 2周目: ストリングス/ドラム追加）を v2 候補とする（H6 への部分対応）
- クリップ保証（ベロシティ範囲・負時刻なし・次コードへの不要な重なりなし）は既存テストの対象のまま

## 10. 実装に必要なデータ構造

新規の型はほぼ不要で、既存構造の**エントリ追加**で成立する見込み。

| 構造 | 場所 | Ballad での使い方 |
|---|---|---|
| `RhythmAxes`（style/feel/beatsPerBar） | `src/lib/performance/model/` | `style: 'ballad'`, `feel: 'straight'`, 4/4（6/8 は既存 sixEight と役割分担） |
| `StylePreset`（velocity/microtiming/gate/swing） | `src/lib/performance/styles/` | Ballad プロファイル値を追加 |
| `BassProfile` | `src/lib/performance/bass/profiles.ts` | §4 の3プロファイル |
| `AccompanimentVariant` + `StyleRefinement` | 既存バリアント機構 | §3 のパターン群を variants として提供 |
| `LibraryPattern`（完全相対形式） | `src/lib/performance/library/` | §13 の教材 MIDI を相対化して登録。provenance / license 必須 |
| ドラムパターン ID | `DrumKit.swift` + `drumPattern.ts` | §5 の3パターン（ネイティブ・要再ビルド） |
| 教師データ | `docs/style_datasets/ballad_teacher.md` | 仮説の出典と検証結果の記録先 |

新規に必要になり得るもの: 「周回数に応じた段階」を持たせる場合のみ、演奏強度段階（intensity tier）の小さな型（v2 検討。v1 では追加しない）。

## 11. 最小構成の Ballad Engine v1

**スコープ（これだけ作る）**:

1. ピアノ2パターン: `ballad.hold`（既存 ballad の改良）＋ `ballad.arp.slow`（バリアントとして）
2. ベース1プロファイル: `BALLAD_WARM`（§4）
3. ドラム: 既存の静かなパターンの流用可否をまず検証し、不足時のみ `balladBrush` を追加
4. フレーズ終端の音数減（既存 `twoFourBar` の Ballad 調整）
5. Humanize / ベロシティの Ballad プロファイル値の決定とキャリブレーションテスト

**やらないこと**: ストリングス、セクション自動判定、周回数ダイナミクス、UI の新スタイル選択枠（既存の ballad リズム枠を置き換える形で出す）、他4スタイル。

**接続方法**: 既存 13 リズムの `ballad` を v1 実装で差し替え、`AccompanimentVariant` で hold / arp を切替可能にする。保存形式・課金・他リズムには触れない。

## 12. 検証方法

1. **定量（実装前後の比較）**: `ACCOMPANIMENT_REPORT` で before/after を生成し、Ballad エントリの音数・ベロシティ標準偏差・音域・最大同時発音を比較する（`docs/performance/reports/` の既存フロー）。
2. **不変条件**: 既存 `midiIntegrity` / `determinism` / `stress` / `rhythmSanity` を全パス。
3. **聴感チェックリスト（実機・Dev Client）**: 固定進行 A〜D（`fixtures.ts`）を Ballad で再生し、
   - 歌を上に乗せて邪魔にならないか（H6/H10）
   - 4小節目に「呼吸」を感じるか（H7）
   - ベースが動きすぎていないか（H4）
   を主観3段階で記録する。判定者はオーナー。
4. **仮説の検証**: §13 の教材 MIDI が用意でき次第、`LibraryPattern` 形式へ相対化して H1〜H10 と突き合わせ、教師データファイルの該当列に結果を記入する。
5. **回帰**: 他12リズムのレポート数値が変化していないこと（Ballad 以外の diff がゼロ）。

## 13. 合法的に用意すべき MIDI 教材の条件

以下のいずれかを満たすもの**のみ**を教材として `LibraryPattern` に登録できる（vision §9・implementation 作業原則）。

1. **オーナー自身の演奏・打ち込み**によるオリジナルの伴奏パターン（教師曲の「雰囲気の研究成果」を自分の演奏として作ったもの。特定曲のコピー採譜は不可）
2. **明示的ライセンスで再利用可能な MIDI**（CC0 / CC-BY 等。CC-BY は帰属表示を `provenance` に記録）
3. **権利消滅（パブリックドメイン）の楽曲**の、権利上問題のない打ち込み
4. **購入・許諾済みで、アプリ組み込みが許される**商用 MIDI ライブラリ（ライセンス文言の確認必須）

登録時の必須メタデータ（`LibraryPattern` に定義済み）: `sourceType` / `license` / 出典。
禁止事項: 市販曲 MIDI の無断ダウンロード、耳コピによる特定曲アレンジの実質的コピー、
ストリーミング音源からの収録。教師データの曲は**傾向を言語化する参照**に留める。
