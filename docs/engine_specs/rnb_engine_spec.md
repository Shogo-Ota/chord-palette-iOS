## 1. R&B Engine がユーザーへ提供する体験

- R&B を選ぶだけで、**音数が少なく、後ノリで呼吸するグルーヴ**が返ってくる。
- 目指す聴感（教材要素12項目の言い換え）:
  - ハーフタイムの重心（スネアが 3 拍目）でゆったり大きく揺れる
  - コードは疎く、**鳴らさない場所**が音楽になる
  - ベースは少ない音数で深くグルーヴし、ゴースト的な弱音が呼吸を作る
- 非目標: Rhodes 音色・ネオソウルの複雑なリハーモナイズ（エンジンはユーザーの付けたテンションのみ鳴らす）。特定曲の再現。
- **準備中の理由（正直さの原則）**: ハーフタイムのネイティブドラムパターンが存在しない。ドラム追加（要再ビルド）が v1 の前提条件。

## 2. 仮説としての共通伴奏特徴

R&B Engine の初期設計ターゲットとして、以下を作業仮説（`HYPOTHESIS`）とする。
これは Reference Songs（LEFT RIGHT、Best Part、Pink + White、LA・LA・LA LOVE SONG 等）を
**計測して得た範囲ではなく**、一般的な音楽知識および教材要素キーワードに基づく
**未検証の設計仮説**である。曲名は方向性の参照であり、傾向の根拠データではない。

| # | 内容 | 分類 | 根拠の種類 |
|---|------|------|-----------|
| H1 | R&B Engine の初期設計ターゲットとして、65–95 BPM を想定する | HYPOTHESIS | 一般的な音楽知識（未計測） |
| H2 | ドラムはハーフタイム（スネア3拍目）＋ゴーストノートの弱音 | HYPOTHESIS | 教材要素リスト |
| H3 | コードは m9 / Maj7 / 11th / 13th が常用され、2〜4声の疎な置き方 | HYPOTHESIS | 教材要素リスト |
| H4 | 全体が後ノリ（レイドバック）。ジャストからの遅延量の実測値は UNKNOWN。設計仮説として数十 ms 程度を将来の DESIGN_TARGET 候補とする（未計測・MEASURED ではない） | HYPOTHESIS | 教材要素リスト（数値は未計測） |
| H5 | ベースは音数最小でシンコペを含み、休符がグルーヴを作る | HYPOTHESIS | 教材要素リスト |

R&B エンジン本体は未実装のため、§7 の microtiming ms 目安（例: `{6,22}`）も
**未検証の DESIGN_TARGET 候補 / HYPOTHESIS** であり、教師曲の MEASURED ではない。
曲単位の具体演奏はすべて `UNKNOWN`。

## 3. 必要なピアノ（コンプ）パターン（候補）

| ID 案 | 内容 | 対応仮説 |
|---|---|---|
| `rnb.space` | 小節頭＋シンコペ 1〜2 打の疎な置き方 | H3, H8 |
| `rnb.pulse` | 2・4 拍裏の柔らかい刻み | H5, H8 |
| フレーズ変化形 | 4小節目の「引き」 | H9 |

- Ballad Engine（relaxed）の疎さ＋レイドバックの資産を最も流用できるスタイル。差分は**ハーフタイムの重心**と**シンコペ位置**。

## 4. 必要なベースパターン（候補）

| ID 案 | figures | 特徴 |
|---|---|---|
| `RNB_DEEP` | rootOnly＋シンコペ配置 | 音数最小・休符主導（H5）。スケルトン側 hits 調整が必要 |
| `RNB_WALK` | rootFifth＋approach 低頻度 | コード変わり目のみ滑らかに動く（H7） |

## 5. 必要なドラムパターン（候補）— **v1 の前提条件**

| ID 案 | 内容 |
|---|---|
| `halfTime` | キック1拍目＋スネア3拍目＋ベロシティが波打つ16分ハット（H2, H10） |

- ネイティブ `DrumKit.swift` への追加＝**要再ビルド**。ゴーストノート（弱スネア）は DrumHit の低 vel エントリで表現可能。

## 6. Rhodes の役割（将来）

- v1 では実装しない。E.Piano 音色（実装済み）を R&B のデフォルト音色候補とするかは聴感判断（音色はユーザー選択が原則のため、プリセットで強制しない方針を推奨）。

## 7. Humanize 方針

以下の数値はすべて **未検証の DESIGN_TARGET 候補 / HYPOTHESIS** であり、教師曲の MEASURED ではない。

- **最大レイドバック**: microtiming を正方向（遅らせ）に広く取る想定。参考として Ballad 実装の chord `{2,12}` ms（DESIGN_TARGET）より深い `{6,22}` ms を将来候補とする（H4・未計測）
- humanizeScale は大きめ（1.2 を候補）— 機械的正確さの対極（H6）
- ドラムはハット・ゴーストのベロシティ変動を大きく、キックは安定

## 8. ボイシング方針

- 共通音保持を最優先し、半音のボイスリーディングを好む（H7）
- 声部数は少なめ（2〜4声）を許容 — 疎さが様式（H3）
- テンションはユーザー指定分のみ（既存方針）

## 9. ダイナミクス方針

- ベロシティ幅は広く、**同一フレーズ内で波打たせる**（H6）— 既存 velocity 層の humanize 幅拡大で近似
- パート間の呼吸（H8）: chord と bass の同時打点を減らす配置（スケルトン設計時に位相をずらす）
- 4小節目は「引き」（H9）— twoFourBar の thinning 側を強く

## 10. 実装に必要なデータ構造

Band 仕様 §10 と同じ枠組み。R&B 固有の追加: `GrooveId` に `halfTime`（型 1 行＋ネイティブ）、
シンコペ配置の疎なスケルトン（`StylePreset` 1 エントリ）。

## 11. 最小構成の R&B Engine v1

**スコープ**:

1. ネイティブ `halfTime` ドラムパターン追加（要再ビルド・EAS 待ち時間が支配的）
2. `rnb.space` スケルトン（疎な配置＋深いレイドバック＋広い humanize）
3. ベース `RNB_DEEP`
4. スタイルカードの R&B を「準備中」→ 選択可能へ切替（プリセット: rnb.space + halfTime、余韻 自然、音域 高め）
5. キャリブレーションテストで数値凍結

**やらないこと**: Rhodes 音色追加、リハーモナイズ、セクション判定、他スタイル。

**順序の注意**: Dance と同じくネイティブ変更を含むため、JS 3スタイルの後に回す。
Dance と同一ビルドにまとめると EAS 待ちが 1 回で済む。

## 12. 検証方法

共通枠組み（Ballad 仕様 §12）に加え、R&B 固有の観点:
レイドバックが「もたり」でなく「ノリ」に聞こえるか（H4）、
疎な配置でもコードの機能が伝わるか（H3/H8）、
30分以上の連続再生でタイミング後退が蓄積しないか（レイドバックは相対値で、絶対時刻に累積させない）。
