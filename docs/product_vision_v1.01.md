# Code Palette 設計思想 v1.01

> 注記（2026-08-02 オーナー承認）:
> - 本文中の「Code Palette」は製品「Chord Palette / コードパレット」を指す。
> - 他の仕様文書と矛盾する場合は、最新の文書を優先する。

## 1. プロダクトの使命

Code Paletteは、AIが曲を丸ごと作るアプリではない。

目指すのは、

「創作の楽しさを残しながら、伴奏制作の難しさと手間を減らすこと」

である。

GarageBandや一般的なDAWは自由度が高い一方、初心者は何から始めればよいか分かりにくい。

SunoのようなAI作曲サービスは短時間で完成度の高い曲を生成できる一方、ユーザー自身が試行錯誤して作った感覚が薄くなりやすい。

Code Paletteは、その中間を担う。

ユーザーが自分でコードを選び、並べ、音楽の方向性を決める。

アプリは、その選択を自然で気持ちいい伴奏へ変換する。

創作の主役は、常にユーザーである。

## 2. 提供価値

### 作曲経験のないユーザー

コードを並べるだけで、コードの響きや連なりの魅力をすぐに体験できる。

音楽理論やDTM操作を知らなくても、

「自分で音楽を作った」

という感覚を得られる。

### 作曲・DTM経験のあるユーザー

入力したコード進行から、編集可能な高品質伴奏MIDIを短時間で得られる。

ゼロから伴奏を打ち込む時間を減らし、作曲、アレンジ、音色選びなど、より創造的な作業に集中できる。

## 3. プロダクトの中核

Code Paletteの競争力は、機能数ではない。

中核価値は次の3点である。

1. コードを直感的に選べること
2. 選んだ結果がすぐ音楽として鳴ること
3. 伴奏が自然で、もう一度聴きたくなること

今後の開発では、特に3番目の「伴奏品質」を重点的に強化する。

## 4. v1.01の位置付け

v1.01は、完全な次世代伴奏エンジンを完成させるアップデートではない。

v1.01の目的は、

「将来の高品質伴奏エンジンへ移行できる土台を作りつつ、現在の伴奏を明確に改善すること」

である。

今回のアップデートでは、次を重視する。

- 現在の再生品質を悪化させない
- 機械的な演奏感を軽減する
- 低音だけが鳴る等の再生不具合を減らす
- 伴奏データを将来拡張しやすい構造へ整理する
- スタイル追加に耐えられる設計へ移行する
- MIDI出力を将来実装しやすくする
- 初心者向けのシンプルなUXを維持する

## 5. 伴奏スタイル

長期的には、以下の5種類を伴奏スタイルとして扱う。

- Ballad
- Band
- City
- Dance
- R&B

これらは厳密な音楽ジャンル分類ではない。

ユーザーが「どのような伴奏にしたいか」を直感的に選ぶための分類である。

ただし、v1.01ですべてを完成させる必要はない。

現在実装されている伴奏を優先し、将来5種類へ展開できる共通構造を準備する。

## 6. スタイルとリズムフィールを分ける

以下は伴奏スタイルである。

- Ballad
- Band
- City
- Dance
- R&B

以下はリズムフィールであり、スタイルとは別軸である。

- Straight
- Shuffle
- Swing

将来的には、

Style × Rhythm Feel × Instrument Pattern

の組み合わせで伴奏を生成できる構造を目指す。

ただし、v1.01ではUI上の選択肢をむやみに増やさない。

## 7. 伴奏品質の定義

伴奏品質は、単なるランダムなHumanizeではない。

次の要素の組み合わせで評価する。

### タイミング

- 音楽的なアクセントに応じた微細な前後
- パート間の自然なタイミング関係
- 全音符を一律にランダム移動しないこと

### ベロシティ

- 拍やフレーズに応じた強弱
- 同じベロシティの連続を避ける
- ランダムではなく、音楽的な規則を持たせる

### 音価

- すべての音を同じ割合で伸ばさない
- スタッカート、通常、レガートを区別する
- 次のコードやフレーズとの関係を考慮する

### ボイシング

- 不自然な大跳躍を避ける
- 共通音を活用する
- 各楽器に適した音域を守る
- 低音域の過密な和音を避ける

### グルーヴ

- ベース、ドラム、コード楽器が別々に動くのではなく、互いに関係する
- アクセント、休符、シンコペーションを設計する
- 反復の中に小さな変化を持たせる

### ダイナミクス

- 小節ごとに同じことを繰り返すだけにしない
- セクションやフレーズ終端で変化をつける
- 常に全パートを鳴らさず、余白を作る

## 8. Humanizeの原則

Humanizeは「完全なランダム化」にしてはいけない。

悪いHumanizeの例：

- すべてのノートを一律に±10ms動かす
- 毎回完全に異なる結果になる
- コード内の音が不自然にバラバラになる
- ドラム、ベース、ピアノの関係が崩れる

望ましいHumanize：

- 再現可能なシードを使用する
- パートごとに揺れ幅を変える
- コード内の音はグループとして扱う
- 強拍、弱拍、シンコペーションを考慮する
- タイミング、ベロシティ、音価を別々に制御する
- BPMに応じて揺れ幅を調整する

## 9. MIDIデータベースの役割

Apple Musicプレイリストは、伴奏研究の候補曲一覧である。

これらのURLだけから、音源やMIDIを自動取得できるとは想定しない。

Ballad:
https://music.apple.com/jp/playlist/ballad/pl.u-6mo44ZZHBqLKpva

Band:
https://music.apple.com/jp/playlist/band/pl.u-6mo445WcBqLKpva

City:
https://music.apple.com/jp/playlist/city/pl.u-BNA66X6F1VbRydl

Dance:
https://music.apple.com/jp/playlist/dance/pl.u-BNA66lJt1VbRydl

R&B:
https://music.apple.com/jp/playlist/r-b/pl.u-LdbqqB4txGP6KBV

使用するMIDI、MusicXML、音声素材は、権利上利用可能なものに限定する。

市販曲のMIDIや音声を、そのままアプリに収録・再配布してはいけない。

目的は楽曲のコピーではなく、合法的に入手した資料から以下を抽象化することである。

- リズムパターン
- ベロシティ傾向
- 音価
- ボイシング
- 音域
- アクセント
- 休符
- パート間の関係
- フレーズの変化
- ダイナミクス

最終的にアプリへ搭載するのは、特定楽曲を再現するMIDIではなく、十分に抽象化されたオリジナル伴奏ルールである。

## 10. UX原則

### シンプルさを維持する

ユーザーに内部の複雑さを見せない。

初心者は、

1. コードを選ぶ
2. 並べる
3. 再生する

だけで楽しめること。

### 上級機能は段階的に開示する

詳細設定やMIDI出力は、必要なユーザーだけが使える場所に置く。

メイン画面へ大量の設定項目を追加しない。

### 音で理解できるようにする

スタイル名を読ませるだけでなく、タップすればすぐ違いを聴ける設計を優先する。

## 11. やらないこと

少なくともv1.01では、以下を優先しない。

- 曲全体のAI自動生成
- 歌詞生成
- AIボーカル生成
- 大規模なメロディ生成
- 多数の細かいジャンル選択
- 高度なDAW機能の再現
- 不要な設定画面の追加
- 音楽的根拠のないランダム化

## 12. 開発判断基準

新しい機能や変更を提案するときは、次の順で評価する。

1. 再生安定性は上がるか
2. 伴奏の聴感品質は上がるか
3. 初心者の操作は難しくならないか
4. ユーザーの創作感を奪わないか
5. 将来のMIDI出力や伴奏エンジン拡張につながるか
6. 保守しやすい構造か

判断に迷った場合、単純に機能を増やすのではなく、

「最小の変更で、聴感上の改善が最も大きい案」

を選択する。

## 13. 最終ビジョン

作曲経験のない人にとって、Code Paletteはコードの魅力を体験できる入口になる。

作曲経験者にとって、Code Paletteは高品質な伴奏MIDIジェネレーターになる。

ユーザーがコード進行を入力し、スタイルを選ぶだけで、

「自分で作った」
「この伴奏をそのまま使いたい」

と感じられることが最終目標である。
