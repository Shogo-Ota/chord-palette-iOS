# Chord Palette OSS Comparison

**Phase:** 2 — OSS 調査  
**日付:** 2026-07-25  
**前提:** 実行時依存（iOS/Expo バンドル）と開発用解析ツールを分離して評価する。  
**方針:** 単純導入ではなく、**採用 / 参考実装 / 不採用** を明示する。

---

## 1. 評価軸

| 軸 | 意味 |
|---|---|
| ライセンス | 商用 iOS アプリ同梱・派生利用の可否 |
| 保守状況 | 直近コミット / npm・PyPI 更新 |
| TypeScript 親和性 | RN/Expo 実行時、または TS ツールチェーンでの利用しやすさ |
| コード解析 | コードシンボル・構成音・度数 |
| MIDI 解析 | ノート/ベロシティ/タイミング抽出 |
| テンション対応 | 9/11/13/altered 等 |
| グルーヴ解析 | velocity / microtiming / swing / humanize |
| 導入コスト | バンドルサイズ・ネイティブ依存・学習コスト |
| 将来性 | Chord Palette の「曲解析→特徴抽象→KB蓄積」への適合 |

**判定ラベル**

- **採用** — 実行時または公式ツールチェーンに取り込む
- **参考実装** — コード/データから学び、自前実装・KB に反映（依存はしない／開発用のみ）
- **不採用** — 現状スコープでは取り込まない

## 3. 個別評価

### 3.1 Tonal（`tonal` / `@tonaljs/*`）

| 項目 | 評価 |
|---|---|
| 概要 | TS 製音楽理論ライブラリ。Chord / Interval / Key / Roman / MIDI 変換 |
| ライセンス | MIT |
| 保守 | 活発（v6系、2026年更新） |
| TS 親和性 | 最高。Expo にそのまま載せられる |
| 強み | コード検出・音程・ローマ数字・辞書が充実。テンション名の正規化に使える |
| 弱み | グルーヴ/伴奏なし。表記が Chord Palette UI 規約と一致しない場合がある |
| 導入コスト | 低（tree-shake 可能なモジュール分割） |

**提案: 採用（限定）**

- **実行時全面置換はしない**（既存 `rootOffset`+`suffix` モデルと UI 表記を守る）
- 次のどちらかで段階導入:
  1. **開発時ゴールデン比較** — 自前 `INTERVALS` / 表示名を Tonal 出力と突合するテスト補助
  2. **薄いアダプタ** — `Chord.parse` / `Interval` のみ使い、表示・候補カタログは自前 KB が正

Chord Palette の「正」は引き続き `project/docs/music/` と自前定義。Tonal は検証器・パーサ補助。

---

### 3.2 Magenta（`@magenta/music` / Magenta Python）

| 項目 | 評価 |
|---|---|
| 概要 | ML によるメロディ/ドラム生成、GrooVAE（humanize） |
| ライセンス | Apache-2.0 |
| 保守 | リポジトリは存続。`@magenta/music` npm は長期間大きな更新が薄い |
| TS 親和性 | ブラウザ向け。RN/iOS では TF.js・モデルサイズが重い |
| 強み | Groove の hit/velocity/offset 表現、humanize の概念モデル |
| 弱み | アプリ同梱コスト大。コード理論エンジンではない |

**提案: 参考実装**

- GrooVAE の **(hit, velocity, offset)** 表現を Phase 6 Groove Engine のデータモデル参考にする
- モデル推論自体はアプリに載せない（将来クラウド解析なら再検討）

---

### 3.3 Groove MIDI Dataset（GMD）

| 項目 | 評価 |
|---|---|
| 概要 | 人間演奏ドラム MIDI + メタデータ（約 13.6h / 1150 files） |
| ライセンス | **CC BY 4.0**（帰属表示が必要） |
| 保守 | データセットとして安定 |
| 強み | velocity / microtiming / style ラベル付き。抽象特徴抽出の教師データに最適 |
| 弱み | ドラム特化。ピアノ伴奏は別ソースが必要。原曲コピー禁止ポリシーとの境界を設計で守る必要あり |

**提案: 採用（開発データ）**

- 実行時バンドルしない
- オフライン解析パイプラインで **スタイル特徴（swing比、ghost密度、accent 分布）** だけを抽出し Knowledge Base / groove profile JSON へ蓄積
- 帰属: ドキュメントと解析ツール README に CC BY 表示

---

### 3.4 Basic Pitch（Spotify）

| 項目 | 評価 |
|---|---|
| 概要 | 音声→MIDI 自動採譜（Python + `@spotify/basic-pitch` TS） |
| ライセンス | Apache-2.0 |
| 保守 | Python 側が本流。TS 側は更新が遅い |
| 強み | 「好きな曲を解析」ワークフローの入口 |
| 弱み | コード推定は別段必要。ポリフォニー精度に限界。オンデバイスは重量級 |

**提案: 参考実装 → 将来採用候補（開発パイプライン）**

- 当面は **開発用 Python ツール** として評価・PoC
- アプリ実行時同梱はしない（Phase 6 の入力段として設計に位置づけ）
- 出力 MIDI → pretty-midi / 自前特徴抽出 → KB（コピーではなく抽象特徴のみ）

---

### 3.5 Impro-Visor

| 項目 | 評価 |
|---|---|
| 概要 | Jazz 教育向けリードシート / ボイシング / 伴奏スタイル（Java） |
| ライセンス | **GPL-2.0** |
| 保守 | 安定版中心、活発な製品開発としては低調 |
| 強み | ジャズテンション・ボイシング・スタイル記述の知識が豊富 |
| 弱み | GPL のためアプリへのコード取り込みは不可（派生義務リスク） |

**提案: 不採用（バイナリ/コード取り込み禁止）**

- 概念・用語・スタイル分類の **学習参考のみ**（KB 執筆の参考文献レベル）
- コード・スタイルファイルのコピーは行わない

---

### 3.6 pretty-midi

| 項目 | 評価 |
|---|---|
| 概要 | Python MIDI 読み書き・解析ユーティリティ |
| ライセンス | MIT |
| 保守 | 安定（2025リリースあり） |
| 強み | velocity / onset / instrument トラック解析が容易。GMD・Basic Pitch 出力と相性良い |
| 弱み | TS/RN 実行時には使えない |

**提案: 採用（開発ツール）**

- `tools/groove-analyze/`（将来）の標準 MIDI I/O
- Phase 6 特徴抽出の実装言語を Python にする場合の第一候補

---

### 3.7 miditok

| 項目 | 評価 |
|---|---|
| 概要 | MIDI→トークン（REMI 等）変換。ML 学習用 |
| ライセンス | MIT |
| 保守 | 活発 |
| 強み | 生成モデル学習の前処理 |
| 弱み | Chord Palette の即時ニーズ（コード候補・伴奏プロファイル）と遠い |

**提案: 参考実装**

- 将来「スタイル学習モデル」を自前でやる段階まで保留
- トークン設計（pitch/velocity/time-shift）は Groove イベントスキーマの参考

---

### 3.8 music21

| 項目 | 評価 |
|---|---|
| 概要 | 計算音楽学ツールキット（和声・ローマ数字・解析） |
| ライセンス | BSD-3-Clause（コーパスは別ライセンスに注意。no-corpus 版あり） |
| 保守 | 非常に活発 |
| 強み | コード解析・度数・転調・教育的理論カバレッジが厚い |
| 弱み | Python のみ。実行時不可。重い |

**提案: 採用（開発ツール）**

- Knowledge Base / テンションカタログの **理論検証用オラクル**
- Tonal（TS）と双対で「表示・intervals・MIDI」一致テストの期待値生成に使える
- コーパス同梱版をアプリに入れない（ライセンス混在回避）

## 4. Chord Palette への適用マップ

```text
[実行時 iOS アプリ]
  自前 ChordDefinition + Voicing + GrooveProfile
  └─（任意・限定）Tonal アダプタ（parse/検証）

[開発・オフライン解析]
  Basic Pitch (audio→MIDI)      … 参考→将来
       ↓
  pretty-midi / GMD             … MIDI・ドラム解析
       ↓
  music21 / Tonal               … 和声・テンション検証
       ↓
  特徴抽出（velocity/timing/swing/voicing stats）
       ↓
  project/docs/music + groove profiles  … 知識のみ蓄積
       ↓
  アプリの伴奏エンジンがプロファイルを消費

[取り込まない]
  Impro-Visor コード（GPL）
  Magenta モデルのアプリ同梱
  miditok（当面）
```

## 5. 推奨決定（承認用）

| 対象 | 判定 | 用途 |
|---|---|---|
| Tonal | **採用（限定）** | TS 側の理論検証・将来の薄い parse アダプタ |
| music21 | **採用（開発）** | KB/カタログの理論オラクル |
| pretty-midi | **採用（開発）** | MIDI 解析パイプライン |
| Groove MIDI Dataset | **採用（開発データ）** | ドラム・Humanize 特徴の教師データ（CC BY 表示） |
| Basic Pitch | **参考→将来開発採用** | 曲→MIDI 入口（アプリ非同梱） |
| Magenta | **参考実装** | Groove 表現・humanize 概念 |
| miditok | **参考実装** | 将来 ML 用に保留 |
| Impro-Visor | **不採用** | GPL。知識の読書参考のみ |

### 代替案

1. **Tonal を実行時に使わない**（開発テストのみ）— バンドルゼロを最優先する場合  
2. **Basic Pitch を早期に tools 配下へ正式採用** — 「曲解析ワークフロー」を先行実証したい場合  
3. **GMD を使わず手作りプロファイルのみ** — ライセンス表示運用を避けたい場合（非推奨: データ根拠が弱くなる）
